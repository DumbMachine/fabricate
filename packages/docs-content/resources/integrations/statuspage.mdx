Pages, components, and incidents. Local Statuspage v1 that keeps status state
across requests.

## Integration

| | Details |
| --- | --- |
| API | Statuspage v1 |
| Auth | Synthetic bearer token. Statuspage's API key is `Authorization: OAuth`; Fabricate accepts `Bearer` because the proxy injects it. |
| Hosts | `api.statuspage.io` |
| Direct URL | Yes |
| Transparent proxy | Yes |

### Start it with a direct URL

Use `fab run` without `--proxy`. The command below downloads Fabricate's
example manifest directly, so you do not need to clone this repository.
Fabricate injects a URL and a short-lived token for the service name in that
manifest.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-statuspage.yaml | \
  fab run /dev/stdin -- \
    sh -c 'curl -sS -H "Authorization: Bearer $FAB_STATUSPAGE_TOKEN" \
      "$FAB_STATUSPAGE_URL/v1/pages/page-acme/incidents"'
```

The service is named `statuspage` in the example manifest, so the variables are
`FAB_STATUSPAGE_URL` and `FAB_STATUSPAGE_TOKEN`.

### Start it through the proxy

Use this when your app uses the normal Statuspage URLs and follows standard
proxy and CA environment variables. This one-paste check calls Statuspage's
normal production hostname; replace the final `curl` with your app. Omit
`$FAB_STATUSPAGE_TOKEN` here: the proxy replaces `Authorization` on routed
hosts with the environment's ephemeral token.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-statuspage.yaml | \
  fab run /dev/stdin --proxy -- \
    curl -sS https://api.statuspage.io/v1/pages/page-acme/incidents
```

Fabricate handles `api.statuspage.io` locally. Other hosts are forwarded
unchanged; set `proxy.unknown_hosts: reject` for an isolated, fail-closed
conformance test.

The proxy will not help an application that pins certificates or ignores proxy
settings. In that case, use the direct URL.
