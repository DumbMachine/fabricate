Zoho Books API v3 that keeps the Acme ledger across requests.

## Integration

| | Details |
| --- | --- |
| API | Zoho Books v3 |
| Auth | Synthetic bearer token. Zoho Books live API uses `Authorization: Zoho-oauthtoken`. |
| Hosts | `www.zohoapis.com` |
| Direct URL | Yes |
| Transparent proxy | Yes |

### Start it with a direct URL

Use `fab run` without `--proxy`. The command below downloads Fabricate's
example manifest directly, so you do not need to clone this repository.
Fabricate injects a URL and a short-lived token for the service name in that
manifest.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-zohobooks.yaml | \
  fab run /dev/stdin -- \
    sh -c 'curl -sS -H "Authorization: Bearer $FAB_ZOHOBOOKS_TOKEN" \
      "$FAB_ZOHOBOOKS_URL/books/v3/invoices/INV-4812?organization_id=org-acme"'
```

The service is named `zohobooks` in the example manifest, so the variables are
`FAB_ZOHOBOOKS_URL` and `FAB_ZOHOBOOKS_TOKEN`. Every Books call except the
organization list takes `organization_id=org-acme`.

### Start it through the proxy

Use this when your app uses the normal Zoho Books URLs and follows standard
proxy and CA environment variables. This one-paste check calls Zoho's normal
production hostname; replace the final `curl` with your app. Omit
`$FAB_ZOHOBOOKS_TOKEN` here: the proxy replaces `Authorization` on routed hosts
with the environment's ephemeral token.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-zohobooks.yaml | \
  fab run /dev/stdin --proxy -- \
    curl -sS "https://www.zohoapis.com/books/v3/invoices/INV-4812?organization_id=org-acme"
```

Fabricate handles `www.zohoapis.com` paths under `/books/` locally. Paths
outside that prefix, including Zoho Inventory under `/inventory/`, are not this
resource. Other hosts are forwarded unchanged; set `proxy.unknown_hosts: reject`
for an isolated, fail-closed conformance test.

The proxy will not help an application that pins certificates or ignores proxy
settings. In that case, use the direct URL.
