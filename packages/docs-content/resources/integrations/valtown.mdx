Vals, blobs, and sqlite. Local Val Town v1 that keeps val state across
requests.

## Integration

| | Details |
| --- | --- |
| API | Val Town v1 |
| Auth | Synthetic bearer token |
| Hosts | `api.val.town` |
| Direct URL | Yes |
| Transparent proxy | Yes |

### Start it with a direct URL

Use `fab run` without `--proxy`. The command below downloads Fabricate's
example manifest directly, so you do not need to clone this repository.
Fabricate injects a URL and a short-lived token for the service name in that
manifest.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-valtown.yaml | \
  fab run /dev/stdin -- \
    sh -c 'curl -sS -H "Authorization: Bearer $FAB_VALTOWN_TOKEN" \
      "$FAB_VALTOWN_URL/v2/vals"'
```

The service is named `valtown` in the example manifest, so the variables are
`FAB_VALTOWN_URL` and `FAB_VALTOWN_TOKEN`.

The response is the Acme val list:

### Start it through the proxy

Use this when your app uses the normal Val Town URLs. This one-paste check
calls Val Town's production hostname. Omit `$FAB_VALTOWN_TOKEN`; the proxy replaces `Authorization` on that host with the environment's ephemeral token.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-valtown.yaml | \
  fab run /dev/stdin --proxy -- \
    curl -sS https://api.val.town/v2/vals
```

Fabricate handles `api.val.town` locally. Other hosts are forwarded unchanged.
