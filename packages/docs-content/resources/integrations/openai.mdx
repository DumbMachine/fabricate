Responses, chat completions, embeddings, and models. Local OpenAI v1 that
keeps response state across requests.

## Integration

| | Details |
| --- | --- |
| API | OpenAI v1 |
| Auth | Synthetic bearer token |
| Hosts | `api.openai.com` |
| Direct URL | Yes |
| Transparent proxy | Yes |

### Start it with a direct URL

Use `fab run` without `--proxy`. The command below downloads Fabricate's
example manifest directly, so you do not need to clone this repository.
Fabricate injects a URL and a short-lived token for the service name in that
manifest.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-openai.yaml | \
  fab run --environment /dev/stdin -- \
    sh -c 'curl -sS -H "Authorization: Bearer $FAB_OPENAI_TOKEN" \
      "$FAB_OPENAI_URL/v1/responses/resp_checkout"'
```

The service is named `openai` in the example manifest, so the variables are
`FAB_OPENAI_URL` and `FAB_OPENAI_TOKEN`.

### Start it through the proxy

Use this when your app uses the normal OpenAI URLs. This one-paste check
calls OpenAI's production hostname; the proxy supplies the local token.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-openai.yaml | \
  fab run --environment /dev/stdin --proxy -- \
    curl -sS https://api.openai.com/v1/responses/resp_checkout
```

Fabricate handles `api.openai.com` locally. Other hosts are forwarded unchanged.
