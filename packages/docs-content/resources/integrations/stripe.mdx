Customers, invoices, charges, subscriptions, and payment intents. Local
Stripe v1 that keeps billing state across requests.

## Integration

| | Details |
| --- | --- |
| API | Stripe v1 |
| Auth | Synthetic bearer token |
| Hosts | `api.stripe.com` |
| Direct URL | Yes |
| Transparent proxy | Yes |

### Start it with a direct URL

Use `fab run` without `--proxy`. The command below downloads Fabricate's
example manifest directly, so you do not need to clone this repository.
Fabricate injects a URL and a short-lived token for the service name in that
manifest.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-stripe.yaml | \
  fab run /dev/stdin -- \
    sh -c 'curl -sS -H "Authorization: Bearer $FAB_STRIPE_TOKEN" \
      "$FAB_STRIPE_URL/v1/customers"'
```

The service is named `stripe` in the example manifest, so the variables are
`FAB_STRIPE_URL` and `FAB_STRIPE_TOKEN`.

The response is the Acme customer list:

### Start it through the proxy

Use this when your app uses the normal Stripe URLs. This one-paste check
calls Stripe's production hostname. Omit `$FAB_STRIPE_TOKEN`; the proxy replaces `Authorization` on that host with the environment's ephemeral token.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-stripe.yaml | \
  fab run /dev/stdin --proxy -- \
    curl -sS https://api.stripe.com/v1/customers
```

Fabricate handles `api.stripe.com` locally. Other hosts are forwarded unchanged.
