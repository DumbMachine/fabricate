Projects, branches, endpoints, and organizations. Local Neon v1 that keeps
project state across requests.

## Integration

| | Details |
| --- | --- |
| API | Neon v1 |
| Auth | Synthetic bearer token |
| Hosts | `console.neon.tech` |
| Direct URL | Yes |
| Transparent proxy | Yes |

### Start it with a direct URL

Use `fab run` without `--proxy`. The command below downloads Fabricate's
example manifest directly, so you do not need to clone this repository.
Fabricate injects a URL and a short-lived token for the service name in that
manifest.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-neon.yaml | \
  fab run --environment /dev/stdin -- \
    sh -c 'curl -sS -H "Authorization: Bearer $FAB_NEON_TOKEN" \
      "$FAB_NEON_URL/api/v2/projects"'
```

The service is named `neon` in the example manifest, so the variables are
`FAB_NEON_URL` and `FAB_NEON_TOKEN`.

### Start it through the proxy

Use this when your app uses the normal Neon URLs. This one-paste check
calls Neon's production hostname; the proxy supplies the local token.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-neon.yaml | \
  fab run --environment /dev/stdin --proxy -- \
    curl -sS https://console.neon.tech/api/v2/projects
```

Fabricate handles `console.neon.tech` locally. Other hosts are forwarded unchanged.
