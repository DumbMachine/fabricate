Boards, posts, users, and votes. Local Canny API v1 that keeps feedback
state across requests.

## Integration

| | Details |
| --- | --- |
| API | Canny API v1 |
| Auth | Synthetic bearer token. Canny's live API sends `apiKey` in the JSON body; Fabricate ignores that field. |
| Hosts | `canny.io` (`/api/v1/`) |
| Direct URL | Yes |
| Transparent proxy | Yes |

### Start it with a direct URL

Use `fab run` without `--proxy`. The command below downloads Fabricate's
example manifest directly, so you do not need to clone this repository.
Fabricate injects a URL and a short-lived token for the service name in that
manifest.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-canny.yaml | \
  fab run /dev/stdin -- \
    sh -c 'curl -sS -H "Authorization: Bearer $FAB_CANNY_TOKEN" -H "Content-Type: application/json" \
      -d "{}" "$FAB_CANNY_URL/api/v1/posts/list"'
```

The service is named `canny` in the example manifest, so the variables are
`FAB_CANNY_URL` and `FAB_CANNY_TOKEN`.

Canny's production clients POST JSON to `/api/v1/posts/list` and put the
secret in `apiKey`. Send `Authorization: Bearer` instead. A body `apiKey` is
optional and is not checked.

### Start it through the proxy

Use this when your app uses the normal Canny URLs and follows standard proxy
and CA environment variables. This one-paste check calls Canny's normal
production hostname; replace the final `curl` with your app. Omit
`$FAB_CANNY_TOKEN` here: the proxy replaces `Authorization` on routed hosts
with the environment's ephemeral token. Leave `apiKey` out of the body.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-canny.yaml | \
  fab run /dev/stdin --proxy -- \
    curl -sS -H "Content-Type: application/json" -d "{}" https://canny.io/api/v1/posts/list
```

Fabricate handles `canny.io` paths under `/api/v1/` locally. Other hosts are
forwarded unchanged; set `proxy.unknown_hosts: reject` for an isolated,
fail-closed conformance test.

The proxy will not help an application that pins certificates or ignores proxy
settings. In that case, use the direct URL.
