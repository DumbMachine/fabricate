Admins, contacts, and conversations. Local Intercom 2.16 that keeps inbox
state across requests.

## Integration

| | Details |
| --- | --- |
| API | Intercom 2.16 |
| Auth | Synthetic bearer token |
| Hosts | `api.intercom.io`, `api.eu.intercom.io`, `api.au.intercom.io` |
| Direct URL | Yes |
| Transparent proxy | Yes |

### Start it with a direct URL

Use `fab run` without `--proxy`. The command below downloads Fabricate's
example manifest directly, so you do not need to clone this repository.
Fabricate injects a URL and a short-lived token for the service name in that
manifest.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-intercom.yaml | \
  fab run /dev/stdin -- \
    sh -c 'curl -sS -H "Authorization: Bearer $FAB_INTERCOM_TOKEN" \
      "$FAB_INTERCOM_URL/conversations"'
```

The service is named `intercom` in the example manifest, so the variables are
`FAB_INTERCOM_URL` and `FAB_INTERCOM_TOKEN`.

### Start it through the proxy

Use this when your app uses the normal Intercom URLs and follows standard
proxy and CA environment variables. This one-paste check calls Intercom's
normal production hostname; replace the final `sh -c ...` command with your
app.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-intercom.yaml | \
  fab run /dev/stdin --proxy -- \
    curl -sS https://api.intercom.io/conversations
```

Fabricate handles `api.intercom.io`, `api.eu.intercom.io`, and
`api.au.intercom.io` locally. Other hosts are forwarded unchanged; set
`proxy.unknown_hosts: reject` for an isolated, fail-closed conformance test.

The proxy will not help an application that pins certificates or ignores proxy
settings. In that case, use the direct URL.
