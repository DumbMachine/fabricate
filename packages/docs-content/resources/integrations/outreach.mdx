## Integration

| | Details |
| --- | --- |
| API | Outreach API v2 |

| Direct URL | Yes |
| Transparent proxy | Yes |

### Start it with a direct URL

Use `fab run` without `--proxy`. The command below downloads Fabricate's
example manifest directly, so you do not need to clone this repository.
Fabricate injects a URL and a short-lived token for the service name in that
manifest.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-outreach.yaml | \
  fab run /dev/stdin -- \
    sh -c 'curl -sS -H "Authorization: Bearer $FAB_OUTREACH_TOKEN" \
      "$FAB_OUTREACH_URL/api/v2/sequences"'
```

The service is named `outreach` in the example manifest, so the variables are
`FAB_OUTREACH_URL` and `FAB_OUTREACH_TOKEN`.

### Start it through the proxy

Use this when your app uses the normal Outreach URLs and follows standard proxy
and CA environment variables. This one-paste check calls Outreach's normal
production hostname; replace the final `curl` with your app. Omit
`$FAB_OUTREACH_TOKEN` here: the proxy replaces `Authorization` on routed hosts
with the environment's ephemeral token.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-outreach.yaml | \
  fab run /dev/stdin --proxy -- \
    curl -sS https://api.outreach.io/api/v2/sequences
```

Fabricate handles `api.outreach.io` locally. Other hosts are forwarded unchanged;
set `proxy.unknown_hosts: reject` for an isolated, fail-closed conformance test.

The proxy will not help an application that pins certificates or ignores proxy
settings. In that case, use the direct URL.
