that keeps contract state across requests.

## Integration

| | Details |
| --- | --- |
| API | Ironclad Public API v1 |
| Auth | Synthetic bearer token |
| Hosts | `na1.ironcladapp.com` |
| Direct URL | Yes |
| Transparent proxy | Yes |

### Start it with a direct URL

Use `fab run` without `--proxy`. The command below downloads Fabricate's
example manifest directly, so you do not need to clone this repository.
Fabricate injects a URL and a short-lived token for the service name in that
manifest.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-ironclad.yaml | \
  fab run /dev/stdin -- \
    sh -c 'curl -sS -H "Authorization: Bearer $FAB_IRONCLAD_TOKEN" \
      "$FAB_IRONCLAD_URL/public/api/v1/workflows?status=active&status=completed"'
```

The service is named `ironclad` in the example manifest, so the variables are
`FAB_IRONCLAD_URL` and `FAB_IRONCLAD_TOKEN`.

An omitted `status` filter returns active workflows only. This request repeats
`status` so the completed Fernworks MSA is included with the two workflows
still in review.

### Start it through the proxy

Use this when your app uses the normal Ironclad URLs and follows standard proxy
and CA environment variables. This one-paste check calls Ironclad's normal
production hostname; replace the final `curl` with your app. Omit
`$FAB_IRONCLAD_TOKEN` here: the proxy replaces `Authorization` on routed hosts
with the environment's ephemeral token.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-ironclad.yaml | \
  fab run /dev/stdin --proxy -- \
    curl -sS "https://na1.ironcladapp.com/public/api/v1/workflows?status=active&status=completed"
```

Fabricate handles `na1.ironcladapp.com` locally. Other hosts are forwarded
unchanged; set `proxy.unknown_hosts: reject` for an isolated, fail-closed
conformance test.

The proxy will not help an application that pins certificates or ignores proxy
settings. In that case, use the direct URL.
