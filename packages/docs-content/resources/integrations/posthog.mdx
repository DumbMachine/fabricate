Feature flags, insights, dashboards, cohorts, and experiments. Local PostHog
v1 that keeps project state across requests.

## Integration

| | Details |
| --- | --- |
| API | PostHog v1 |
| Auth | Synthetic bearer token |
| Hosts | `us.posthog.com` |
| Direct URL | Yes |
| Transparent proxy | Yes |

### Start it with a direct URL

Use `fab run` without `--proxy`. The command below downloads Fabricate's
example manifest directly, so you do not need to clone this repository.
Fabricate injects a URL and a short-lived token for the service name in that
manifest.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-posthog.yaml | \
  fab run --environment /dev/stdin -- \
    sh -c 'curl -sS -H "Authorization: Bearer $FAB_POSTHOG_TOKEN" \
      "$FAB_POSTHOG_URL/api/projects/1/feature_flags/"'
```

The service is named `posthog` in the example manifest, so the variables are
`FAB_POSTHOG_URL` and `FAB_POSTHOG_TOKEN`.

The response is the Acme feature-flag list:

### Start it through the proxy

Use this when your app uses the normal PostHog URLs. This one-paste check
calls PostHog's production hostname; the proxy supplies the local token.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-posthog.yaml | \
  fab run --environment /dev/stdin --proxy -- \
    curl -sS https://us.posthog.com/api/projects/1/feature_flags/
```

Fabricate handles `us.posthog.com` locally. Other hosts are forwarded unchanged.

| `posthog.acme-flags.v1` | Acme production analytics: ~120 flags, insights, dashboards, cohorts, experiments, and persons. Needles: `checkout_reliability`, Contoso SSO / `contoso-eu`, INV-4812 / Northwind, fernworks CSV, Adatum DNS, LakeTech webhooks, TinyShop refund, BrightPath keys, Fabrikam SCIM `req_7Q4K2`. |
