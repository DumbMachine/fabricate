Fabricate ships a Exa v1 resource with a local API driven by the official Exa OpenAPI document and a synthetic bearer token. Every operation in that document is implemented. The included Acme Exa environment seeds the walkthrough scenario.

## Scenarios

| Scenario | What it gives you |
| --- | --- |
| `exa.minimal.v1` | Empty Exa state for a clean test. |
| `exa.acme-tasks.v1` | Research tasks for checkout reliability, Contoso SSO, and INV-4812. |

## Integration options

| Option | Supported | Use it when |
| --- | --- | --- |
| Direct base URL | Yes | Your client can use a local URL or root URL. |
| Transparent proxy | Yes | Your client must keep Exa’s normal hostnames. |

### Start it with a direct URL

Use `fab run` without `--proxy`. The command below downloads Fabricate's
example manifest directly, so you do not need to clone this repository.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-exa.yaml | \
  fab run --environment /dev/stdin -- \
    sh -c 'curl -sS -H "Authorization: Bearer $FAB_EXA_TOKEN" "$FAB_EXA_URL/research/v0/tasks"'
```

The service is named `exa` in the example manifest, so the variables are
`FAB_EXA_URL` and `FAB_EXA_TOKEN`.

### Start it through the proxy

Use this when your app uses the normal Exa URLs. This one-paste check
calls Exa's production hostname; the proxy supplies the local token.

```bash
curl -fsSL https://raw.githubusercontent.com/DumbMachine/fabricate/main/environments/acme-exa.yaml | \
  fab run --environment /dev/stdin --proxy -- \
    curl -sS https://api.exa.ai/research/v0/tasks
```

Fabricate handles `api.exa.ai` locally. Other hosts are forwarded unchanged.
